<a id="runtime-error-labelled-build-error"></a>
## 1. `simulators/jneuroml.run_lems` labels mid-run jLEMS aborts as BUILD_ERROR (severity: medium)

**Observed.** A probe network generated by `protocols.generate.write_probe` for the Maex and De Schutter
(1998) granule cell (`models/candidates/GranCellLayer@cee86047/NeuroML2/Granule_98.cell.nml`,
0 / +0.05 / -0.05 nA steps from 300 ms, dt 0.01 ms) exits 1. jLEMS prints

```
SEVERE: (ERROR) org.lemsml.jlems.core.run.RuntimeError: Error at PathDerivedVariable eval(): tgt: null[HHExpRate]; sin: n[gateHHrates]; tgtvar: r; path: forwardRate/r
Note: LEMS model description was successfully parsed, and simulation started (t = 0.31162 sec)
This error *MAY* be caused by too large a time step (dt = 1.0E-5 sec currently)
```

`run_lems` returns `RunStatus.BUILD_ERROR` because the status rule is "non-zero exit and no
`Finished N steps` line". The simulation had run 311.6 ms. Reducing dt to 0.002 and 0.001 ms
does not remove the failure; a single population at +0.01 nA runs to 1000 ms. The -0.05 nA step
into a 10 um soma with 0.033 mS/cm2 leak (input resistance of order 10 GOhm) drives V far outside
the range where the HH exponential rates are finite. The same happens for
`MiglioreEtAl14_OlfactoryBulb3D@eaad1c8f/.../GC_soma.cell.nml` (8 um soma). Evidence:
`docs/m0_evidence/model_curation/verification.json` (earlier run, `injection_attempts`) and
reproductions under `work/tmp/model-curation/diag/`.

**Why it matters.** `validation.fingerprint.classify` maps BUILD/RUNTIME to class 2 (non-executable)
and UNSTABLE to class 3. A mutant that makes the membrane potential diverge (e.g. `scale_capacitance`
x0.1 or a large `shift_reversal`) can abort jLEMS inside a rate expression before any output is
written, and would then be counted as "could not be built" rather than "numerically unstable".

**Proposed change (core owner).** In `run_lems`, when the output contains
`simulation started (t = ...)`, return `RUNTIME_ERROR` (never `BUILD_ERROR`), and put the parsed
start time in `SimResult.message`. Optionally map `PathDerivedVariable eval()` errors after start to
`UNSTABLE`, which would need an agreed rule because not every such error is a voltage blow-up.

<a id="validator-npe"></a>
## 2. `JNeuroML.validate` returns `valid=None` (tool failure) when jNeuroML crashes on a malformed include (severity: low)

`jnml -validate SolinasEtAl-GolgiCell@ab450696/NeuroML2/TestSoma_HELPER.net.nml` exits 1 with
`java.lang.NullPointerException at java.io.File.<init> ... NeuroMLConverter.loadNeuroML`, and no
`Validated N files` summary line, so the adapter returns `valid=None`, "unrecognised validator
output". The underlying cause is the model: the included cell file uses `<include file=...>`, and
validating that cell file directly gives `cvc-complex-type.3.2.2: Attribute 'file' is not allowed
to appear in element 'include'`. The spec says tool problems must never be confused with model
problems. A structural mutant that corrupts an include could hit the same NPE and be reported as a
tool failure.
**Proposed change:** when the output contains a Java exception trace from
`org.neuroml.model.util` while loading a file that exists, report `valid=False` with the exception
line, keeping `None` for missing Java/jar, timeouts and OS errors.

<a id="rheobase-initial-hi"></a>
## 3. `rheobase.initial_hi_nA: 0.5` can crash jLEMS on very small cells (severity: medium, config/protocols)

For the candidates above, 0.05 nA already aborted jLEMS (item 1). `rheobase.search` starts with a grid
from 0 to `hi_nA`, and a failed simulation makes the whole search return `status="error"`. The
curation screen worked around it by retrying the injection check at 0.005 and 0.0005 nA and starting
the search at 10x the amplitude that ran (`verify_candidates.py`, `run_probes`). With that
workaround, 0.005 nA ran for both cells, and the searches found rheobases of 0.0051 nA (granule)
and 0.0026 nA (GC soma), 100-200x below the default upper bracket. **Proposed change
(protocols/config owner):** when the first bracketing grid fails, retry with `hi_nA / expand`
before reporting `error`, or derive `hi_nA` per model from input resistance. Otherwise the full study
cannot include small-soma models such as cerebellar or olfactory granule cells.

<a id="canonical-window"></a>
## 4. `validation.canonical.canonical_protocol` window = earliest pulseGenerator, whatever it targets (severity: medium for these candidates)

`canonical_protocol` collects every `pulseGenerator` in the harness NeuroML files and uses the one with
the smallest delay as the analysis window. For three candidate harnesses this is not the pulse that
tests the recorded cell:

| candidate | shipped inputs | window chosen | consequence |
|---|---|---|---|
| `smith2013_singlecomp` (`LEMS_singleCompAllChans.xml`) | -0.01 nA 100-200 ms, +0.05 nA 300-400 ms | 100-200 ms | all 7 spikes (305-399 ms) fall outside the window, so canonical spike features read a silent cell |
| `prinz2004_abpd` / `prinz2004_lp` (`LEMS_Fig2a.xml`) | three pulses to AB_PD[0] (0-100 ms -0.2 nA, 0-1000 ms -0.03 nA, 4000-5000 ms -0.2 nA); none to LP | 0-100 ms (earliest, ties broken by file order) | window is 2 % of the 5 s run; for LP the pulses do not even target the recorded cell (LP is driven only by a 0 nS graded synapse) |
| `solinas2007_soma_helper` (screened out) | -5 pA 200-400 ms, +40 pA 800-1000 ms | 200-400 ms | depolarising test outside the window |

**Proposed change (validation owner):** restrict components to `inputList`/`explicitInput` entries that
target the population and cell in the harness `OutputColumn` path. When several remain, either use
the union window (first onset to last offset) or record every window and let the canonical test
use the whole simulation. This must be decided before any of these candidates enter the study,
because the canonical test defines "silent".

<a id="no-single-cell-harness"></a>
## 5. Models without a shipped single-cell harness (contract gap)

`maex1998_granule` and `maex1998_golgi` ship only a network simulation (`LEMS_GranCellLayer.xml`,
mossy-fibre-driven, tested upstream only with jNeuroML_NEURON). `ModelRecord.harness_lems` is left
empty in `data/model_candidates.csv`. The spec defines the canonical protocol as "the simulation
distributed with the model". These models therefore need either an explicit
NeuroSem-authored canonical harness, recorded as a deviation in the preregistration, or exclusion
from the canonical-vs-battery comparison. `models.Workspace.harness_path` and
`validation.execution.run_canonical` currently assume a harness exists.

<a id="test-location"></a>
## 6. Model-curation tests live outside `testpaths` (request to the tests owner; severity: low)

`docs/m0_evidence/model_curation/test_model_candidates.py` is not collected by a plain `pytest` run,
because `pyproject.toml` sets `testpaths = ["tests"]` and `tests/` is not owned by model-curation.
It must be run explicitly (`python -m pytest docs/m0_evidence/model_curation/test_model_candidates.py`).
**Proposed change:** move it to `tests/integration/test_model_candidates.py` (the basename is unique)
and change its `HERE` constant to `REPO_ROOT / "docs" / "m0_evidence" / "model_curation"`. It imports
`curate_candidates` and `verify_candidates` from that folder through `sys.path`. Tests named
`test_evidence_*` only check that stored evidence files agree with each other. The other tests are
live checks against the pinned files, jNeuroML and jLEMS.

<a id="dt-hyperpolarising-abort"></a>
## 7. dt 0.025 ms aborts jLEMS on a hyperpolarising step in the Maex Golgi cell (observation for numerics)

On a work copy of `GranCellLayer@cee86047/NeuroML2/Golgi_98.cell.nml`, `P07_hyperpolarizing_step` at
-0.1 nA exits 1 at dt 0.025 ms with `RuntimeError: Error at PathDerivedVariable eval(): ... path:
reverseRate/r` (forwardRate/r when Ih is blocked). This happens with and without Ih. The same
protocol runs to completion at dt 0.01 ms, and `P01_baseline` runs at both time steps. The adapter
labels this `build_error` (item 1). This matters for any dt ladder that starts at 0.025 ms. For this
cell, a failure at coarse dt is numerical (fixed-step forward Euler), not structural. Scratch
reproductions: `work/tmp/model-curation/diag/ihblock_*`.

**Addendum: Ih-block runs abort at strong hyperpolarisation.** In the curation Ih-block control
(`verify_candidates.py`, run `2026-09-13T16:00:56+00:00_aa8fa6a0`), the h density was set to 0 at
dt 0.01 ms. Some protocols then exited 1 with `build_error`: P08 and S01 for `maex1998_golgi` and
`prinz2004_abpd`, and S01 for `maex1998_granule`. The error was `... sin: Golgi_H_CML[ionChannelHH];
tgtvar: fcond; path: gates[*]/fcond`, or the H_STG / Gran_H_98 equivalent. The same protocols also
failed when the h `channelDensity` element was removed instead. The error then came from other
channels (`Golgi_KDr_CML_m_alpha_rate`, `Na_STG ... fcond`, `Gran_KDr_98_m_alpha_rate`; scratch
`work/tmp/model-curation/diag/rm_*`). In P07, which still ran, the blocked Golgi cell sat at
-162 mV. So without Ih these high-input-resistance cells are driven to non-physiological potentials,
where HH rate exponentials overflow. The failure is runaway voltage in the whole cell, not an
artefact of the zeroed channel. It is the failure class of item 1. A mutant that deletes or zeroes
Ih in such a cell would currently be classed as non-executable rather than numerically unstable.
