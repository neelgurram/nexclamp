## In plain English

- This table lists the 36 published papers and software tools that come closest to Neuraxis.
- Every building block Neuraxis uses already exists somewhere. Examples:
  - re-checking a NeuroML model against saved outputs (OMV);
  - measuring many features across many stimuli (NeuroML-DB, HippoUnit);
  - rerunning one protocol battery on each model version (the cardiac Web Lab);
  - seeding faults into simulation models and picking a small test set (Simulink testing papers).
- No source we found does the whole combination for neuron models:
  - deliberately break models in controlled ways;
  - find the breaks that the usual single test misses;
  - pick a small stimulus battery;
  - show the battery still works on models and fault types it was not chosen on.
- The closest sources each cover two or three of those steps. None covers all of them.
- "Not found" is not proof that it does not exist. See the limits in `PRIOR_ART_AUDIT.md`, section 7.

## How rows were chosen and ranked

- **Rows 1-29:** every work rated closeness 3 (the highest rating given) in `docs/novelty_matrix.csv`. Two pairs of duplicates were merged: the two OMV records, and the Patten-Elliott preprint with its journal version.
- **Rows 30-36:** established systems and surveys rated closeness 2, added because the brief names them:
  - the NeuroML ecosystem paper that describes OMV;
  - eFEL and BluePyOpt, the feature-validation tools;
  - surveys of test-suite minimisation, mutation testing, metamorphic testing, and scientific-software testing.
- **Ranking.** The novelty matrix gives all 29 of rows 1-29 the same score, so the order among them is a judgement. Two things decided it:
  1. how many of the six Neuraxis claims a work touches (listed in the packets);
  2. whether it studies neuron or electrophysiology models with the same kinds of tools.
- **Top five.** The top five are the four neuron or electrophysiology lines that the hostile-reviewer stress test (`stress_test_r2.json`) rated with the highest confidence, plus the Druckmann stimulus-selection paper. The Simulink mutation line (row 6) and the ion-channel design line (row 7) are close behind. They are worth a manual look too.
- **Order after row 5** is approximate.

## Column meanings

| Column | Meaning |
|---|---|
| Full text inspected | "yes" only if this pass or a recorded prior deep read read the full text (paper body, or README and source code for software). A keyword scan or abstract counts as "no". |
| Transformation testing | Checks that an edited, converted, re-implemented or translated model or program still behaves like its reference. Transforming inputs, as metamorphic testing does, does not count. |
| Controlled mutation | Deliberate, catalogued faults or variants used to measure what tests detect |
| Multiple protocols | More than one stimulation protocol, or more than one kind of test input |
| Ephys features | Extracted electrophysiological features such as spike counts, latencies and AP shape |
| Protocol / suite optimisation | Algorithmic choice, design or minimisation of protocols or tests |
| Held-out generalisation | Evaluation on stimuli, models or fault families not used when building or choosing |
| Coding agent | Code or models generated or edited by an AI system |
| yes / partial / no / unclear | "partial" means the work touches the idea in a weaker or different form; the cell text says how |

## DOI verification

- **Crossref and DataCite.** Every DOI was looked up on 2026-09-16 at `api.crossref.org/works/<DOI>` (or `api.datacite.org` for arXiv DOIs). Each record returned the title shown here.
- **doi.org.** A request to `https://doi.org/<DOI>` returned a redirect to the publisher for every DOI. Some publisher pages then blocked the automated client (HTTP 403 or 429). The DOI still resolved.
- **Kaizen (row 27).** The earlier matrix listed "none retrieved". DataCite has a record for 10.48550/arXiv.2607.04058, so that DOI is used here.
- **OMV (row 1)** is software without a DOI. Its archival URL is the GitHub repository. The eLife ecosystem paper (row 30) describes it.
